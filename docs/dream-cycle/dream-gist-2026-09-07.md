# Intelligence SOTA Report — 2026-09-07

TL;DR: Tonight's intelligence deep-dive found a live tier/model-identity consistency bug in `EnhancedModelRouter.route()` (`v3/@claude-flow/cli/src/ruvector/enhanced-model-router.ts`), the default task-routing path once the neural router is opt-in enabled (`CLAUDE_FLOW_ROUTER_NEURAL=1`, ADR-148/149). When AST/tier3-keyword complexity boosts escalate the *returned* tier past the tier the base bandit router's `modelId` was actually chosen for, the router forwarded that stale, cheaper-tier `modelId` onto the escalated decision anyway — and `agent-execute-core.ts`'s first-call dispatch (ADR-149 iter 13) treats a present `modelId` as an unconditional override of the tier mapping. Net effect: a task correctly escalated to `tier: 3 / model: 'opus'` (e.g. by a single "encryption"/"authentication"/"distributed" keyword) could still silently execute against a cheap haiku-tier `modelId` the neural backend picked before the escalation fired. Fixed by only forwarding `modelId`/`routedBy`/`provider`/`openrouterModel` when the returned tier's model still matches the tier the base router chose them for. Five research roles ran in parallel tonight; four additional code-verified findings (MoE load-balancing loss never applied, SONAManager EWC state never populated, an orphaned RVF-backed SONA implementation, an orphaned semantic-memory-consolidation implementation, and a partial plugin-integrity fix) are documented below as candidates for future nights rather than folded into tonight's patch, per repo convention (one conceptual change per PR) and STEP 1.1's bias toward small, reviewable candidates given the current merge backlog.

## Ruflo Current Capability

`EnhancedModelRouter.route()` (`v3/@claude-flow/cli/src/ruvector/enhanced-model-router.ts:382-542`) is Ruflo's default task-to-model routing entry point (called unconditionally by `agent-tools.ts` whenever a task string is given). Step 4 calls the base bandit `ModelRouter.route()` once to get a coherent `{model, complexity, modelId, provider, openrouterModel}` tuple — `modelId` is always chosen for the same complexity bucket as `model` inside `ModelRouter` (`model-router.ts:634`). Steps 5-6 then independently recompute `finalComplexity` from AST analysis and tier-3 keyword boosts (+0.25 per match, even a single keyword) and pick the *returned* tier/model from that recomputed value — but, before tonight's fix, unconditionally forwarded `baseResult.modelId`/`routedBy`/`provider`/`openrouterModel` onto whichever tier the boosted complexity landed in, with no check that `baseResult.model` (the tier `modelId` was chosen for) matched the tier being returned. `docs/adr/ADR-149-per-model-cost-optimal-routing.md:64,129` documents this pairing as an invariant ("Together they fully describe the decision: mechanism + identity"). `agent-execute-core.ts:579-585` (ADR-149 iter 13) confirmed as the live consumer: first-call dispatch uses `agent.modelId` directly, bypassing the tier→model map entirely, whenever it's present.

Also confirmed via `git show`/branch inspection which of the three prior intelligence findings are merged vs. still open: the Thompson-sampling `priorDecay` fix (#3048/#3049) **is merged** (present in `model-router.ts` at HEAD); the EWC-gate wiring fix (#3109/#3110) and `LearningBridge.consolidate()`'s reward-blind fix (#3159/#3160) are **evaluated but still unmerged** — both bugs remain live in `main` pending human review. Tonight's finding is a fourth, distinct bug in a different file from all three.

Synthesis: Ruflo is the only system surveyed shipping a *combined, running* loop (HNSW + MoE + SONA + EWC++) with its own measured numbers, where the agent frameworks either delegate memory to third parties or route via static rules with no learned or forgetting-aware component. It's behind on external validation: no Ruflo number has been benchmarked against RouterBench/GraphRouter, and a 2026 position paper directly challenges EWC-only regularization (Ruflo's approach) as architecturally insufficient in isolation for agents facing shifting task distributions — both addressable, not fundamental, gaps.

## Hypothesis

> Given `EnhancedModelRouter.route()` escalating a task's returned tier above the tier the base bandit router's `modelId` was chosen for (via AST-complexity averaging or a tier3-keyword boost crossing the haiku/sonnet/opus thresholds), when the candidate fix gates forwarding of `modelId`/`routedBy`/`provider`/`openrouterModel` on `baseResult.model` matching the tier actually being returned, then the `{tier, model, modelId}` triple returned by `route()` should always be internally consistent per ADR-149's documented invariant, subject to: (1) routing decisions that do not cross a tier boundary are unaffected (regression-free); (2) zero added latency (no new network/model calls — the check is a single equality comparison); (3) $0 evaluation cost, deterministic tests only; (4) full existing test suite remains green.

## Scan Findings: memory

**New, code-verified finding — an entire semantic-consolidation implementation is dead code, orphaned in a different layer from the one actually wired to `UnifiedMemoryService`.** The package ships two independent consolidation implementations. The wired one (`consolidator.ts:140-210`, `MemoryConsolidator.dedup()`, invoked from `UnifiedMemoryService.runAutoConsolidation()` and the `nightlyLearner` controller) keys purely on `sha256(content)` — byte-exact hash, cannot catch paraphrases or near-duplicates, even though the adapter it runs against already stores per-entry embeddings and an `HNSWIndex` handle it never queries. The unused one, `MemoryDomainService.consolidate()` (`domain/services/memory-domain-service.ts:135-331`), does exactly what's missing — real embedding-cosine similarity grouping via `repository.searchByVector()` with configurable thresholds (0.95 dedupe / 0.8 merge) — but is never imported outside its own barrel file, isn't even reachable via the package's public `exports` map, and has zero test coverage. First added 2026-08-12, predates and is orthogonal to the three recently-fixed memory bugs (hybridSearch reachability, HybridBackend weights, MMR embedding-cosine — none touched `consolidator.ts` or this file). Industry practice (NVIDIA NeMo Curator's SemDedup, Mem0's fact-consolidation writeups) treats embedding-similarity dedup as standard specifically because hash-exact dedup misses semantic duplicates (Grade B, cross-checked vendor sources). Not implemented tonight — this is a "wire up or delete" architectural decision, not a live incorrect-computation bug, better suited to a dedicated follow-up.
