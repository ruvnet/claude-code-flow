# RSI research review and bounded implementation decision

Reviewed 2026-09-12. This is a targeted primary-source review, including July and
August 2026 work, not a claim to reproduce every method or establish a universal
leaderboard. Results below are the authors' reported findings. No paper supplies
independent evidence for this RuFlo mission.

| Work and version date | Relevant finding | Decision for this mission |
| --- | --- | --- |
| [DGM, v3 2026-03-12](https://arxiv.org/abs/2505.22954v3) | Uses an archive of coding agents and empirical evaluation to explore multiple self-modification lineages. | Retain source and failed branches. A high child score alone does not prove that its optimizer improved. |
| [GEPA, v2 2026-02-14](https://arxiv.org/abs/2507.19457v2) | Uses execution feedback and reflection to propose prompt updates and combine complementary candidates. | Preserve per-task failures and candidate effects. Our native joint-mutation probe is a small design adaptation, not a GEPA implementation or result reproduction. |
| [HGM, v3 2025-10-29](https://arxiv.org/abs/2510.21614v3) | Identifies a mismatch between benchmark performance and ability to produce useful descendants; estimates clade metaproductivity. | Measure descendant improvement under matched costs. Its conditional oracle argument does not prove this empirical RuFlo system. |
| [VISTA, submitted 2026-03-19](https://arxiv.org/abs/2603.18388) | Separates hypotheses from prompt rewrites and verifies hypotheses against feedback, reporting failures of unrestricted reflection. | Bind one explicit hypothesis before execution. Keep immutable evidence of failed hypotheses. |
| [RSIBench-Data, submitted 2026-07-28](https://arxiv.org/abs/2607.25886v1) | Studies agents revising data strategies under a fixed training stack; later attempts often regress from an earlier peak. | Preserve strong checkpoints and measure the entire trajectory. Do not assume that more iterations compound gains. Hosted training services are outside this mission's enabled spending envelope. |
| [AI4AI-Bench, submitted 2026-08-20](https://arxiv.org/abs/2608.20318v1) | Separates changes to learning algorithms from incidental configuration changes, using frozen repositories and from-scratch evaluation. | Design future agent-engineering tasks that modify the improvement mechanism. Its GPU workload is not executed here, and hyperparameter search is not relabeled as algorithm discovery. |
| [Meta^n, submitted 2026-08-25](https://arxiv.org/abs/2608.24735v1) | Applies a fixed meta-operation to growing code and trace inputs, building helper layers and searching an archive of chains. | A future wrapper can consume complete inherited traces while preserving the evaluator. Fixed orchestration alone does not establish safety, independence or recursive efficacy. No Meta^n run is claimed. |
| [S3Gym, submitted 2026-08-31](https://arxiv.org/abs/2608.31100v1) | Separates exploration from held-out verification and finds that history, summary memory and training help differently across tasks. | Compare raw history, learned state and reset/shuffle controls on fresh tasks. Successful self-judgment is insufficient evidence that feedback transfers. |

## What follows from the evidence

The common practical direction is to preserve executable experience, explore
alternative improvement strategies, and evaluate what their descendants can do.
Our inference is that RuFlo needs a measurable outer improver and independent
workloads more than additional promotion counters. No reviewed source establishes
that indefinite iteration necessarily reaches open-ended RSI.

The current native adapter exposes only three retrieval parameters. Its operator
credits are inherited, but the outer Codex process that researches and changes
the proposer is not included in matched control costs. That outer process can
belong to an autonomous system boundary; its presence does not make the measured
inner-loop comparison a complete test of that boundary.

## Hypothesis 3, frozen before mission execution

Observed failure: in epoch 4, two mostly single-axis proposals produced no
adaptive gain, while a fixed joint mutation improved both development splits.
Test whether guaranteeing one joint proposal improves candidate coverage under
the same two evaluated proposals per arm.

The new rule alternates the existing high and low grid corners by epoch parity,
then adds one distinct credit-guided single-axis proposal. The first high corner
was already known to work on this developer-selected workload. Rediscovering its
gain is adaptation to development evidence, not a novel discovery or transfer.
Joint gains allocate credit equally to edited axes, with an explicit allocation
receipt; this is a heuristic, not causal attribution to individual parameters.

Six arms each receive two proposals and 8,040 native calls. Adaptive, frozen,
shuffled and previous-checkpoint credits use the new rule. Static is unchanged.
A sixth `legacy` arm runs the exact version-2 proposer body with uniform credits.
The parent audit adds 1,608 calls, totaling 49,848 calls and 12 candidates per epoch.
At most three mission epochs run under this reviewed hypothesis. Lifetime ceilings,
statistical gates, evaluator identities, corpus and query text are unchanged.

Interpretation is predeclared:

1. New frozen versus legacy uniform estimates the proposer implementation effect.
2. Adaptive versus new frozen estimates the effect of learned credits.
3. Adaptive versus previous credits estimates the latest credit-state effect.
4. Adaptive versus static tests whether learning adds value beyond a strong fixed rule.
5. Gains shared equally by frozen and adaptive do not establish credit-learning benefit.

Tests pin the legacy function to its original Git tree, joint/single coverage,
heuristic credit allocations, exclusion of control/selection feedback, reservation
budgets, crash behavior and the unchanged confirmation contract. Source-specific
replay must cover the original pilot, epoch 4 and every new completed epoch once.

## Path beyond this narrow probe

The next substantive workload should let the agent change an executable proposal,
failure-analysis or experiment-selection procedure and apply that inherited
procedure to fresh real repository tasks. Candidate generation, rejected edits,
training, evaluation and outer-agent work need complete cost records. Run every
control through the same outer process or explicitly isolate and label its effect.
Prefer public development tasks for engineering; reserve independently controlled
sealed tasks for the unchanged final confirmation process.

Three improving descendants, reset/shuffle/predecessor controls, independent
operators, full dollar accounting and external replication are still required.
The existing mission has no approved evaluator keys. No local signing key or
successful replay can substitute for those missing inputs. Continue bounded
research on new evidence; stop redundant experiments and preserve the lifetime
ledger if access or resources block useful work.
